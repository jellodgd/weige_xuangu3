MiniQMT 竞价筛选与下单策略说明

更新时间：2026-07-14　对应程序：jingjia_filter.py　 配置界面：jingjia_filter_qt.py

实盘提醒：实时模式会连接配置文件指定的股票账户，并在 09:27:00 对交易候选股票真实提交限价买单。历史模式只筛选，不下单。

一、整体流程

1. 读取账户与 QMT 配置
2. 09:15:05 准备昨收与日线基准
3. 09:16 前置涨停检查
4. 采集 a～f 六个价格
5. 执行基础六项筛选条件，按需叠加前两日跌幅过滤
6. 保存全部合格股票
7. 按 f 相对 T-3 收盘价涨跌幅取前 N 只
8. 09:27 提交买单
核心原则：满足筛选条件的股票全部保存；但只有 f 相对 T-3交易日收盘价的涨跌幅 最小的前 N 只进入下单流程， 其余合格股票只记录、不交易。

二、配置文件与启动方式

当前默认配置文件为项目根目录：

.\qmt_accounts_config.json

主程序默认也读取这个文件，因此直接启动即可：

python .\jingjia_filter.py

如果希望用界面选择账号和 MiniQMT 路径，可以启动：

run_jingjia_filter_qt.bat

Qt 界面支持：

  • 读取 qmt_accounts_config.json 里的账号列表；
  • 查看配置中的账号，并在下载/检查数据时保存当前界面账号为配置文件当前账号；
  • 查看或调整账号类型：实盘账户 或 模拟账户；
  • 查看或选择 MiniQMT 根目录；
  • 点击“下载近30天数据”时手动补齐 T-3 条件需要的日线缓存；
  • 点击“检查最近三个交易日数据”时检查 T-3 条件依赖的数据是否准备好；
  • 修改单只预算上限比例，默认 20%，可选 20% 至 100%；
  • 勾选“前两日跌幅过滤”后，要求 T-2 和 T-1 当日最大跌幅都不低于所选阈值，默认不勾选，阈值默认 -9%；
  • 点击“启动策略”时不会保存当前界面配置，会按配置文件中的当前账号启动，并在界面里显示策略输出。
如果配置文件没有 active_account_id，程序会默认使用 accounts 列表里的第一个账号。使用前请确认当前账号和 QMT 路径是否符合预期。

三、股票池范围

策略只处理默认实行 10% 涨跌幅限制的沪深主板普通 A 股。

市场保留代码前缀
上海600 / 601 / 603 / 605
深圳000 / 001 / 002 / 003

程序会排除：

  • 名称包含 ST 的股票；
  • 名称以 N 或 C 开头的新股；
  • 名称包含“退”的股票；
  • 创业板、科创板、北交所等非主板股票；
  • 无法取得有效昨收价、涨停价或排序基准价的股票。

四、precheck 与 a～f 采样定义

实时模式会先在 09:15:05 准备股票池、昨日收盘价、当天涨停价， 以及用于最终排序的 T-3 交易日收盘价、T-2/T-1 最大跌幅检查需要的日线最低价。Qt 启动器默认不在启动策略时下载日线， 而是读取手动准备好的本地/服务端缓存；如果勾选“等待运行时在9:00下载近30天数据”， 程序会在交易日 09:00:00 开始下载近 30 天日线。 Qt 启动器也提供“下载近30天数据”和“检查最近三个交易日数据”两个独立按钮，这两个按钮只处理行情缓存，不会连接交易账号或下单。之后按本地电脑时间触发采集， 但价格归属使用的是 QMT 行情返回字段 quote["time"] 转换得到的 quote_time，不是程序本机读取行情的 scan_time。

变量 本地开始采集时间 接受 quote_time 下限 接受 quote_time 上限 说明
precheck09:16:0009:16:0009:18:00前置校验价格，不属于 a～f
a09:20:0309:20:0009:20:20接受 09:20:00 之后的第一条有效行情
b09:21:0009:20:5509:21:20允许目标分钟前 5 秒至目标后 20 秒
c09:22:0009:21:5509:22:20同 b 的窗口口径
d09:23:0009:22:5509:23:20同 b 的窗口口径
e09:24:0009:23:5509:24:20同 b 的窗口口径
f09:25:0509:25:0009:26:59用于最终涨幅筛选和排序计算

采集方式

  • 普通点位默认最多等待 20 秒；
  • 等待期间约每 0.2 秒重新查询一次；
  • 如果触发时已有落在对应 quote_time 窗口内的快照，立即采用；
  • 否则采用等待窗口内第一条符合 quote_time 要求的数据；
  • 成功取得数据的股票会从本轮待查询列表移除，后续重试只请求剩余股票；
  • 每只股票、每个目标时间最多保存一个价格。
precheck 和 f 是特殊点： precheck 会从 09:16:00 持续采到 09:18:00； f 从 09:25:05 开始采，持续到 09:26:30。 只要期间拿到 09:25:00 至 09:26:59 的 quote_time，就记录为 f。

quote_time 与 scan_time 的区别

字段含义是否决定 a～f 归属
quote_time QMT 返回行情里的时间，来自 quote["time"]。 是。只有落在窗口里的 quote_time 才会被接受。
scan_time 本机程序实际调用接口并收到数据的时间。 否。只用于观察程序读取延迟。

五、筛选条件

股票必须同时满足以下六项基础条件。Qt 勾选“前两日跌幅过滤”时，还会叠加第 7 项可选条件。

条件 1：09:16 precheck 价格是涨停价

precheck = 当天涨停价

比较时允许半个最小报价单位的浮点误差。

条件 2：a 涨幅满足可配置条件

a 涨幅 = (a / 昨收价 - 1) × 100%
默认：a 涨幅 > 5%

Qt 启动器里可以把该条件调整为 5%以上 到 9%以上，也可以选择 涨停。 选择百分比时使用严格大于，例如 5%以上 表示 a 涨幅 > 5%，不是大于等于； 选择 涨停 时，要求 a 点价格等于当天涨停价，比较时同样允许半个最小报价单位的误差。

条件 3：a～f 六个价格单调不升

a ≥ b ≥ c ≥ d ≥ e ≥ f

相邻价格比较同样允许半个最小报价单位的误差。

条件 4：f 涨幅在 -1% 至 +3%

f 涨幅 = (f / 昨收价 - 1) × 100%
-1% ≤ f 涨幅 ≤ +3%

上下边界都包含。

条件 5：f 相对 T-3 收盘价涨跌幅在 -10% 至 +10%

T-3 基准涨跌幅 = (f / T-3交易日收盘价 - 1) × 100%
-10% ≤ T-3 基准涨跌幅 ≤ +10%

上下边界都包含。缺少 T-3 交易日收盘价时，该股票不能通过最终筛选。

条件 6：最后阶段跌幅小于 e 到涨停价的距离

(e - f) < (当天涨停价 - e)

这里比较的是绝对价格差，不是百分比。含义是：09:24 到 f 的下跌幅度， 必须小于 e 价格距离当天涨停价的空间。

可选条件 7：T-2/T-1 当日最大跌幅过滤

Qt 启动器里的“前两日跌幅过滤”默认不勾选。不勾选时，不执行该条件；勾选后阈值可选择 -9%、-8%、-7%、-6%，默认 -9%。

T-2最大跌幅 = (T-2最低价 / T-3收盘价 - 1) × 100%
T-1最大跌幅 = (T-1最低价 / T-2收盘价 - 1) × 100%
T-2最大跌幅 ≥ 选择的阈值，且 T-1最大跌幅 ≥ 选择的阈值

缺少对应交易日最低价或前一日收盘价时，勾选该条件后该股票不能通过筛选。

六、最终前五排序规则

1. 全部股票和最终入选股票分别保存

全部股票及失败原因会写入 all CSV；最终按排序取出的前 N 只会写入：

logs\jingjia_filter_selected_YYYYMMDD.csv
logs\jingjia_filter_selected_YYYYMMDD.sel

2. 只有新排序指标前 N 名参与交易

当前不再按 f 涨幅排序，而是按下面的价差升序排序：

排序基准 x = 当前交易日前第 3 个交易日的收盘价
排序值 = (f / x - 1) × 100%
按排序值从小到大取前 N 只

N 默认为 5，可在 Qt 启动器里的“最终下单股票数”修改。

当前交易日x 的日期计算方式
周一早上 09:25 上周三收盘价 f - 上周三收盘价
周四早上 09:25 本周一收盘价 f - 本周一收盘价
  1. 先筛出满足基础条件和已启用可选条件的全部股票；
  2. 为每只股票读取当前交易日前第 3 个交易日的收盘价 x；
  3. 计算 (f / x - 1) × 100%；
  4. 按该涨跌幅从低到高排序；
  5. 排序值相同则按股票代码排序；
  6. 最多取前 N 只作为 09:27 下单对象，并写入 selected CSV / .sel；
  7. 其他合格股票只保留在 all CSV 中，不进入 selected 文件，也不提交订单。
注意：筛选条件中的 f 涨幅在 -1% 至 +3% 仍然使用“昨日收盘价”计算。 新增的 T-3 基准涨跌幅 使用 f / T-3交易日收盘价 - 1 计算； 最终前五排序也使用该 T-3 基准涨跌幅。

七、09:27 下单规则

下单时间

09:27:00

委托价格

原始委托价 = 昨收价 × 1.005
委托价 = round_to_tick(昨收价 × 1.005)

委托价固定为相对昨收上涨 0.5%，不是 f × 1.005， 也不是 09:27 的实时行情价。

资金分配

下单前重新查询 QMT 账户总资产和可用资金。设实际下单股票数量为 N，默认最多为 5，可在 Qt 启动器修改。单只预算上限比例 R 默认 20%，可在 Qt 启动器选择 20% 至 100%。

单只上限 = 账户总资产 × R
平均可用资金 = 可用资金 / N
每只预算 = min(单只上限, 平均可用资金)

当 R 选择 100% 时，等价于不额外限制单只股票上限，只受平均可用资金约束。

委托数量

委托数量 = floor(每只预算 / 委托价 / 100) × 100

委托数量按 100 股整数手向下取整。不足 100 股时，该股票跳过下单。

10:00 未完成订单撤单

程序会记录 09:27 成功提交的策略订单编号。到 10:00:00 时重新查询订单状态； 若订单成交数量小于委托数量，且订单状态仍允许撤单，则提交撤单。 已全部成交、已撤、废单或其他不可撤状态只记录日志，不重复处理。

资金计算没有额外预留手续费。账户资金接近全部分配时，券商端仍可能因为手续费、 冻结资金或其他规则拒绝订单。

九、实时模式与历史模式

模式启动方式是否下单说明
实时模式 python .\jingjia_filter.py 会真实下单 使用实时 quote_time 窗口，09:27 提交买单。
历史模式 python .\jingjia_filter.py --date 20260709 不会下单 用于复盘筛选；历史模式同样会按目标日期的 T-3 交易日收盘价计算筛选条件和排序值。

十、当前限制与风险

  1. 实时模式会真实提交买单，使用前必须确认当前账号和 MiniQMT 路径。
  2. QMT 没有返回合格行情时，仍会出现缺失样本。
  3. T-3 日线收盘价依赖 QMT 日线数据；缺少该基准价的股票不能通过最终筛选。
  4. 委托价固定为昨收上涨 0.5%，可能低于市场价格，因此不保证成交。
  5. 订单提交成功不等于成交成功。
  6. 当前只有 10:00 未完成订单撤单；没有补单、成交复核和重复下单保护。
  7. 同一账户不要重复启动多个策略实例。
