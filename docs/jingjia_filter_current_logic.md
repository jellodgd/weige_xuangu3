# MiniQMT 竞价筛选与下单策略

更新时间：2026-07-09

对应程序：`jingjia_filter.py`

> 实时模式默认连接配置文件中的股票账户，并在满足条件时真实提交买单。历史模式只生成筛选结果，不会下单。

## 1. 策略流程

实时模式每天依次执行：

1. 连接 MiniQMT 行情和交易账户。
2. 到 `09:15:05` 加载沪深主板普通 A 股股票池、读取昨收价并计算当天涨停价。
3. 采集 `09:16:00` 前置校验价，再采集 6 个指定行情时间点的价格。
4. 按基础条件筛选股票；如 Qt 勾选“前两日跌幅过滤”，再叠加 T-2/T-1 最大跌幅条件。
5. 输出全部结果、入选结果和同花顺板块文件。
6. 如果存在入选股票，等待至 `09:27:00`。
7. 查询账户总资产和可用资金，计算每只股票的委托金额。
8. 按昨收价上涨 `0.5%` 对应的价格提交限价买单。
9. 完成后继续运行，等待下一个交易日。

## 2. 股票池

策略只处理主板普通 A 股，即默认实行 10% 涨跌幅限制的股票。

上海市场代码范围：

```text
600 / 601 / 603 / 605
```

深圳市场代码范围：

```text
000 / 001 / 002 / 003
```

程序排除：

- 名称包含 `ST` 的股票；
- 名称以 `N` 或 `C` 开头的新股；
- 名称包含 `退` 的股票；
- 创业板、科创板、北交所等非主板股票。

## 3. a、b、c、d、e、f 的定义

实时模式会先在 `09:15:05` 准备股票池、读取昨收价、当天涨停价、T-3 排序基准，以及 T-2/T-1 最大跌幅检查需要的日线最低价。
Qt 启动器默认不在启动策略时下载日线，而是读取手动准备好的本地/服务端缓存；如果勾选“等待运行时在9:00下载近30天数据”，程序会在交易日 `09:00:00` 开始下载近 30 天日线，下载完成后 `09:15:05` 只读取缓存并准备 T-3 条件。
Qt 启动器也提供“下载近30天数据”和“检查最近三个交易日数据”两个独立按钮，这两个按钮只处理行情缓存，不会连接交易账号或下单。
随后新增一个前置校验点：

| 用途 | 本地开始读取时间 | 实时最低接受 `quote_time` | 实时最高接受 `quote_time` |
| --- | --- | --- | --- |
| `precheck` | `09:16:00` | `09:16:00` | `09:18:00` |

`precheck` 不属于 a～f 六个价格，只用于判断 9:16 的价格是否为当天涨停价。

默认本地触发时间和实时可接受行情时间窗口如下：

| 变量 | 本地开始读取时间 | 实时最低接受 `quote_time` | 实时最高接受 `quote_time` |
| --- | --- | --- | --- |
| `a` | `09:20:03` | `09:20:00` | `09:20:20` |
| `b` | `09:21:00` | `09:20:55` | `09:21:20` |
| `c` | `09:22:00` | `09:21:55` | `09:22:20` |
| `d` | `09:23:00` | `09:22:55` | `09:23:20` |
| `e` | `09:24:00` | `09:23:55` | `09:24:20` |
| `f` | `09:25:05` | `09:25:00` | `09:26:59` |

这里使用的是 QMT 行情返回值中 `time` 字段转换得到的 `quote_time`，不是程序本机读取行情的 `scan_time`。

程序从本地触发时间开始查询，默认最多等待 20 秒，每 0.2 秒重试一次。触发时若 QMT 已有落在对应 `quote_time` 窗口内的快照，立即采用；否则采用等待窗口内第一条满足窗口要求的行情。例如 `b` 在本地 `09:21:00` 开始读取，`quote_time=09:20:55` 到 `09:21:20` 都可以接受。

`precheck` 和 `f` 是例外：`precheck` 会从 `09:16:00` 持续重复获取到 `09:18:00`；`f` 虽然本地开始读取时间是 `09:25:05`，但实时模式会持续重复获取到 `09:26:30`，只要期间拿到 `09:25:00` 至 `09:26:59` 的 `quote_time` 就记录为 `f`。

以上窗口规则用于实时模式；历史模式仍沿用历史 tick 采样逻辑，不按这次实时窗口改动处理。

如果等待窗口内没有取得符合要求的行情，该股票在该点没有样本。缺少 9:16 前置样本或少于 6 个 a～f 样本时不参与最终筛选，原因记录为：

```text
missing_precheck_sample
missing_samples:x/6
```

`scan_time` 仍会写入 CSV，仅用于检查程序什么时候读取了行情，不用于决定 a～f 的归属。

## 4. 最终筛选条件

股票必须同时满足以下全部条件。

### 4.1 9:16 前置价格是涨停价

```text
precheck = 涨停价
```

比较时允许半个最小报价单位的误差，避免浮点数误差导致误判。

### 4.2 a 的当日涨幅满足可配置条件

```text
a涨幅 = (a / 昨收价 - 1) × 100%
默认：a涨幅 > 5%
```

Qt 启动器里可以把该条件调整为 `5%以上` 到 `9%以上`，也可以选择 `涨停`。
选择百分比时使用严格大于，例如 `5%以上` 表示 `a涨幅 > 5%`，不是大于等于；
选择 `涨停` 时，要求 a 点价格等于当天涨停价，比较时同样允许半个最小报价单位的误差。

### 4.3 六个价格单调不升

```text
a >= b >= c >= d >= e >= f
```

相邻价格比较同样允许半个最小报价单位的误差。

### 4.4 f 的当日涨幅在 -1% 至 +3%

计算公式：

```text
f涨幅 = (f / 昨收价 - 1) × 100%
```

要求包含边界：

```text
-1% <= f涨幅 <= +3%
```

### 4.5 最后一分钟降幅小于 e 到涨停价的距离

使用绝对价格差计算，不使用百分比：

```text
(e - f) < (当天涨停价 - e)
```

即 09:24 至 09:25 阶段的价格降幅，必须严格小于 09:24 的价格到当天涨停价之间的距离。

### 4.6 可选：T-2/T-1 当日最大跌幅过滤

Qt 启动器提供“前两日跌幅过滤”复选框，默认不勾选；阈值可选择 `-9%`、`-8%`、`-7%`、`-6%`，默认 `-9%`。

不勾选时，不执行该条件。

勾选时，要求当前交易日前两个交易日都不能出现盘中跌幅过大的情况：

```text
T-2最大跌幅 = (T-2最低价 / T-3收盘价 - 1) × 100%
T-1最大跌幅 = (T-1最低价 / T-2收盘价 - 1) × 100%
```

两项都必须满足：

```text
T-2最大跌幅 >= 选择的阈值
T-1最大跌幅 >= 选择的阈值
```

如果缺少对应交易日的最低价或前一日收盘价，勾选该条件时该股票不能通过筛选。

## 5. 入选结果与交易前 N 名

程序会在 `all` CSV 中保留全部股票及失败原因；`selected` CSV 和 `.sel` 只保留最终按排序取出的前 N 只。

所有入选股票都会写入：

```text
jingjia_filter_selected_YYYYMMDD.csv
jingjia_filter_selected_YYYYMMDD.sel
```

入选结果文件按股票代码排序。旧参数 `--max-selected` 仅为兼容旧命令保留，对当前策略没有作用。

交易阶段会另外计算每只入选股票的 `f` 涨幅：

```text
f涨幅 = (f / 昨收价 - 1) × 100%
```

按 `f` 相对 `T-3收盘价` 的涨跌百分比从小到大排序，只取前 N 只作为09:27的下单对象。N 默认为 5，可在 Qt 启动器里的“最终下单股票数”修改；若入选股票不足 N 只，则对全部入选股票下单。其余合格股票只保留在 `all` CSV 中，不进入 `selected` 文件，也不提交订单。

## 6. 09:27 下单规则

只有实时模式会下单。历史模式不会连接交易账户或提交订单。

### 6.1 下单时间

```text
09:27:00
```

程序在完成筛选和文件输出后等待到该时间，然后依次提交每只入选股票的订单。

### 6.2 委托价格

委托价格对应当日相对昨收上涨 `0.5%`：

```text
原始委托价 = 昨收价 × 1.005
```

程序再按股票的最小报价单位四舍五入：

```text
委托价 = round_to_tick(昨收价 × 1.005)
```

该价格不是 `f × 1.005`，也不是 09:27 的最新行情价。

订单类型：

```text
买入限价单（STOCK_BUY + FIX_PRICE）
```

### 6.3 每只股票的资金分配

09:27 下单前，程序通过交易接口重新查询：

- 账户总资产 `total_asset`；
- 可用资金 `available_cash`。

设实际进入交易前 N 名的股票数量为 `N`，则：

```text
单只上限比例 R = Qt 选择的比例，默认 20%，可选 20% 到 100%
单只上限 = total_asset × R
平均可用资金 = available_cash / N
每只股票预算 = min(单只上限, 平均可用资金)
```

因此：

- 可用资金充足时，每只股票最多使用账户总资产的 R；
- 当 R 选择 `100%` 时，等价于不额外限制单只股票上限，只受平均可用资金约束；
- 可用资金不足时，将当时的可用资金平均分给实际下单的前 N 名股票。

### 6.4 委托数量

A 股按 100 股整数手向下取整：

```text
委托数量 = floor(每只股票预算 / 委托价 / 100) × 100
```

实际委托金额：

```text
实际委托金额 = 委托价 × 委托数量
```

如果预算不足以购买 100 股，该股票跳过下单并记录日志。

资金计算没有额外预留手续费。若账户资金刚好全部分配，券商端仍可能因为手续费或其他冻结资金拒绝订单。

### 6.5 10:00 未完成订单撤单

程序会记录 09:27 成功提交的策略订单编号。到 `10:00:00` 时重新查询订单状态：

- 若订单成交数量小于委托数量，且订单状态仍允许撤单，则提交撤单；
- 已全部成交、已撤、废单或其他不可撤状态只记录日志，不重复处理。

## 7. 订单结果和当前限制

程序记录：

- 股票代码和名称；
- 委托价格；
- 委托数量；
- 委托金额；
- 单只预算；
- QMT 返回的订单编号；
- 订单提交是否成功；
- 10:00 未完成订单撤单结果；
- 异常和错误信息。

QMT 返回正订单编号只表示订单成功提交，不代表已经成交。

当前版本：

- 不检查最终成交数量；
- 10:00 会撤销未完成的策略订单；
- 不对失败订单重新下单；
- 不根据已有持仓扣减单只股票的预算上限额度；
- 不在重复运行时主动检查是否已有同策略订单。

因此实盘运行期间不要重复启动同一账户的策略实例。

## 8. 输出文件

程序每天输出：

```text
logs\jingjia_filter_all_YYYYMMDD.csv
logs\jingjia_filter_selected_YYYYMMDD.csv
logs\jingjia_filter_selected_YYYYMMDD.sel
logs\jingjia_filter_YYYYMMDD.log
```

说明：

- `all` CSV：股票池全部股票、9:16 前置价格、a～f 六个价格、涨幅、行情时间、扫描时间和失败原因；
- `selected` CSV：满足全部条件的股票；
- `.sel`：与 selected CSV 对应的同花顺板块文件；
- `.log`：行情连接、采样、筛选、资金分配、订单提交和 10:00 撤单记录。

CSV 结果文件是一行一个股票；每个成功采样点的精确 `quote_time` 会写入对应的 `quote_time...` 列，例如 `precheck_quote_time_091600`、`quote_time1_092003`、`quote_time2_092100` 等。

CSV 还会输出 `prior_t2_date`、`prior_t2_max_drop_pct`、`prior_t1_date`、`prior_t1_max_drop_pct`，用于复盘“前两日跌幅过滤”是否触发。

## 9. 实时模式与历史模式

### 实时模式

不传 `--date` 时进入实时模式：

```powershell
python .\jingjia_filter.py
```

程序默认提前 120 秒进行准备。QMT不可用时会按照重试间隔持续重连。

### 历史模式

传入日期时只做历史筛选：

```powershell
python .\jingjia_filter.py --date 20260709
```

历史模式不会下单。MiniQMT 历史 tick 数据可能缺少集合竞价阶段数据，因此历史结果取决于本地和服务端可用的 tick 数据。

## 10. 关键风险提示

1. 本策略会在实时模式中真实提交订单。
2. `precheck` 实时模式持续采集到 `09:18:00`；`f` 在本地 `09:25:05` 开始读取，实时模式持续采集到 `09:26:30`，接受 `09:25:00` 至 `09:26:59` 的 `quote_time`。若等待窗口内仍没有合格行情，股票会因缺少样本被排除。
3. 订单价格固定为昨收价上涨0.5%，可能低于09:27市场预期价格，因此不保证成交。
4. 订单提交成功不等于成交成功。
5. 程序目前只有 10:00 未完成订单撤单，没有补单、成交复核和重复下单保护。
